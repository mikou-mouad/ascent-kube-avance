ServiceAccounts : l'identité des pods

POD

son compte

TOKEN

court, monté dans le pod

API

vérifie, puis RBAC

Par défaut, chaque pod reçoit un token dans /var/run/secrets/…

Le back n'appelle jamais l'API : ce token ne sert qu'à un attaquant. On le retire.

La CI reçoit un token de 10 minutes, limité à get, patch deployments.

kind: ServiceAccount
metadata:
  name: back
automountServiceAccountToken: false
---
# dans le Deployment du back
spec:
  serviceAccountName: back

# un token court pour la CI
kubectl create token ci-deployer \
  -n croustino --duration=10m

Les tokens sont projetés : liés au pod, à durée de vie limitée, renouvelés automatiquement. Bonus du TP : décoder le JWT pour voir l'audience et l'expiration.
