Chapitre 9 · Le concept

Mener l'enquête avec jq

Un événement d'audit (simplifié)

{
  "verb": "delete",
  "user": {
    "username": "malik",
    "groups": ["dev", …]},
  "sourceIPs": ["10.10.0.10"],
  "userAgent": "kubectl/v1.34…",
  "objectRef": {
    "resource": "deployments",
    "namespace": "croustino",
    "name": "back"},
  "responseStatus": {"code": 200},
  "requestReceivedTimestamp": "…T03:02:11Z"
}

La requête qui trouve le coupable

sudo jq -c '
  select(.verb == "delete"
    and .objectRef.name == "back")
  | {t: .requestReceivedTimestamp,
     qui: .user.username,
     outil: .userAgent}' \
  /var/log/kubernetes/audit/audit.log

Et les refus ?

select(.responseStatus.code == 403)

Dans le TP, Théo essaie d'abord (403), puis Malik réussit (200). En production, l'audit part vers un système externe (SIEM, Elasticsearch) : un administrateur malveillant pourrait effacer le fichier local.
