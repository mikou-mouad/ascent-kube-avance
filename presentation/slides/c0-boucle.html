Chapitre 0 · Le concept

kubectl apply : ce qui se passe vraiment

1

kubectl envoie le YAML à l'API server

2

L'état voulu est écrit dans etcd

3

Le controller-manager crée 3 pods

4

Le scheduler choisit un nœud pour chacun

5

Le kubelet du nœud lance les conteneurs

Un pod meurt ? L'état réel (2) ≠ l'état voulu (3) : le contrôleur en recrée un. C'est la boucle de réconciliation.

# back.yaml : l'état voulu
apiVersion: apps/v1
kind: Deployment
metadata:
  name: back
spec:
  replicas: 3
  template:
    spec:
      containers:
      - name: back
        image: croustino-back:1.0

$ kubectl apply -f back.yaml

Démonstration possible au TP 02 : supprimer un pod et regarder le Deployment en recréer un. Le YAML est simplifié ici (pas de selector ni de labels) : on le complète au chapitre 2.
